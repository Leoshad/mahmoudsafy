# Our Place — Mahmoud ♥ Safy

Implementation of the user-approved dark / muted pink / gold shared-chat direction. English UI, Arabic or English content. This supersedes the world experiment as the intended product; older files remain intact.

## Run and verify

Node 24.19.0, no third-party runtime dependencies. From `v2/place`:

```sh
npm run check
npm test
npm start
```

`npm start` requires the environment in `.env.example`. The app does not load `.env` implicitly. Keep actual secrets in Render environment settings, never in GitHub or chat.

## Implemented

- Optimistic human messages with a sending / delivered / failed state and idempotent retry. Authenticated server-sent events synchronize both people. AI streams separately, so its network wait does not hold the chat transaction.
- Supabase V2 password authentication with two explicitly allowlisted email addresses. No public registration or identity selector. A confirmed Supabase user ID becomes permanently bound to its assigned name. Encrypted HttpOnly SameSite cookies, server-side logout revocation, origin checks and a short auth verification cache.
- Shared photos with authenticated retrieval. The browser downsizes photos to 1280px and strips metadata by JPEG re-encoding. Server accepts at most 1 MB per photo and 150 MB total; MIME bytes are checked and SVG/HTML are refused. Uploads are shared-room material, not private-preparation attachments.
- Echo uses Responses streaming, `store:false`, `gpt-5.6-luna`, one model request per turn, and a 45-second timeout. Requests and photos are sent only when explicitly invited. Both people can stop shared AI; either person's Just Us pause persists. Ask once shares only its explicit prompt/image during Just Us and never releases a pause.
- Private, durable quiz drafts, edited manually or generated by Echo. Generated proposals require requester review. Only the draft owner can accept a proposal. Launch shares the current question; future questions and correct answers are absent from the partner's API. Questions support 2–4 choices or free responses, optional objective scoring, up to 10 questions, pause by either person, and complete vs abandoned results.
- Our Space: Ideas, Plans, Decisions, Agreements, Discussions, Photos, Results. Independent items with revision checks, completion/resolution, both people's agreement approvals, approvals reset on edits, explicit AI-memory permission, links back to source IDs. No deletion operation in this checkpoint.
- Persistent SQLite/WAL on a required production disk. Text export includes shared messages and only the requesting person's preparation. Restart recovery marks interrupted AI without automatic paid retry.

## Memory boundaries

Data is saved on the server. Each AI turn receives up to 50 recent AI-eligible messages, 30 memory-enabled notes and current activity answers, bounded to 24,000 context characters. Just Us messages and private preparation are excluded. Photos are never included automatically. This is bounded contextual memory, not a promise that all historical chat is always recalled. Text export is not a full database restore tool; keep a disk/database backup for full recovery. No end-to-end encryption claim: the hosting service holds the database and OpenAI processes explicitly shared AI content.

### Profiles and Our Dates — 2026-09-14

Each invited account can edit its own photo, optional bio and birthday. Uploaded profile photos are cropped locally to a square and displayed as circles in chat, profiles, Ocho and Dominoes. Profile names remain the authenticated account names. A hidden age also removes the full birth date and birth year from the partner's API, SSE and export. The month/day remains shared for birthday reminders. The bio is shown only within the profile. Shared crown totals are reused without changing game scoring or crown rules.

Our Space now opens Our Dates. Birthdays are derived from profiles, so editing a birthday updates its single occasion. Other occasions can be shared or private, one-off or annual, associated with either person or both. Only the creator edits/deletes an occasion; each person controls their own reminder offsets and private note. Annual February 29 occasions use February 28 outside leap years. Cairo, Riyadh and UTC are supported; reminders without an occasion time use 09:00 in that zone.

Reminders are calculated server-side, displayed through the existing chat bell, and refreshed by the existing SSE reconnection. Due reminders are retained for 30 days for return visits and dismissed separately for each account. Reminders scheduled before their creation/enabling are not sent retroactively. This release does not implement closed-app push or email notifications. Personal data stays outside automatic Echo context. SQLite state and a new additive photo-owner table use the existing persistent disk.

Validation: 139 Node tests pass, including two-account HTTP/SSE/export privacy, photo ownership, duplicate actions, revisions, reminder timing, annual rollover, leap years, dismissal isolation, and client profile/date form flows. Existing chat and game suites remain passing. ### Echo’s Court — 2026-09-14

A new inline courtroom in Do Together uses a leather-look judge’s desk, Echo’s emblem, a central dialogue pane and both authenticated profile portraits. It opens with the shared panel-reveal behavior, without fullscreen. Cases can also be opened from Court cases in Our Space; both entry points read the same stored case records.

Workflow: invitation and explicit participation consent; independently submitted opening accounts (server-sealed from the partner until both submit); balanced, individually addressed Echo questions; factual review and separate confirmations by both people; a reasoned advisory finding with references to both accounts. Either person can pause, release only their own pause, or close without a finding. A review request retains the original session and finding, and starts a newly consented session in the same case. Corrections and new evidence invalidate the factual approvals. Shared-message evidence is copied from the database; uploaded images are labeled as submitted evidence, not independently verified facts. Court material is excluded from normal Echo chat memory.

Echo uses the existing gpt-5.6-luna Responses integration with one strict function response per explicit Ask Echo action. The server validates stages, question ownership, balanced opportunities, factual approval and referenced record IDs. A 60-second timeout, the existing budget ledger, transactional receipts and cancelled-job checks prevent duplicate billing actions and stale findings. Restart recovery releases interrupted pending court steps without automatic paid retries. Paused global Echo permissions require an explicit Ask Echo once action.

Case files show the finding or current position first, with expandable accounts, reasons, disputed facts, questions, evidence and previous sessions. Download record produces a self-contained HTML document including submitted evidence images; Print / Save PDF uses the browser print destination. This supports Arabic text and avoids a separate paid document service. The print script is protected by a static CSP hash; document content is escaped and authenticated projections preserve sealed statements in exports.

Validation: 149 tests passed, including two-account HTTP case completion, evidence/export escaping, statement privacy, role and revision checks, impartial hearing gates, review preservation, cancellation, restart recovery and client draft preservation. Provider transport and judge answers were mocked in tests; no new billed live-model case was run. Local browser preview is blocked in this environment, so mobile visual review and a real two-person judging session remain user acceptance checks. Findings are advisory, not legal rulings or claims of perfect impartiality. No changes to game scores, crowns, V1, main or authentication configuration.

Function response format follows https://developers.openai.com/api/docs/guides/function-calling .


Court focus update: explicitly opening Echo’s Court now maximizes it automatically. The dialogue uses the available height; compact layouts react to the visual viewport (including the mobile keyboard), and session tools sit behind a disclosure. Court export keeps authentication inside the app: record HTML is fetched with the current same-origin session before offering a local download or a sandboxed print preview. The preview uses the app's existing CSP and a dedicated print stylesheet; standalone downloads retain embedded styling and evidence images. Automated tests cover authenticated download preparation, readable session-expiry handling, and failed/non-HTML responses. Native mobile print UI still needs device verification.

Draw Together provides a persistent shared canvas and an optional six-round Draw & Guess match (three drawing and three guessing turns per person). Both accounts accept, then explicitly request one budgeted Echo word deck; each round starts when both are ready. Difficulty and Arabic/English words are selectable. Correct answers earn 10 points, or 5 after the guesser's hint; the server owns scoring and deadlines. Pauses require each pausing player to resume. A shared crown preference defaults off and is frozen when a match is created; only a completed, non-tied eligible match records one deduplicated competitive win. Current and past eligibility never changes retroactively. Crown details show the prospective drawing setting.

Drawing points are normalized, bounded and persisted in idempotent segments; only the active artist may draw in guessing mode. The shared mode permits both players. Canvas generations reject stale writes after clearing or round changes, and undo removes only the caller's latest stroke. Failed segments remain locally retryable with their original action IDs; unsynced strokes can be discarded explicitly. PNG download and saving to Our Space use the existing photo storage. The current canvas is persisted; save any drawing you want to retain before clearing or advancing to another round. Match results retain scores, not all past canvases.

Drawing tests cover two authenticated HTTP sessions, private words in snapshots and exports, ownership, idempotency, timers and independent pauses, full matches, ties, excluded results, prospective settings, and UI canvas/guess input preservation. AI generation uses the existing budget and model; tests inject a deck and do not spend live AI credit. Actual phone drawing feel and fullscreen layout still require device review.
